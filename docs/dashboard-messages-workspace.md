# Messages-only dashboards and workspace layout

The player, owner and admin dashboards now expose Messages rather than Meetings & messages. They no longer load the meeting service/editor or render meeting cards. The tournament page no longer loads the meeting panel. Old #meetings links normalize to #messages, preserving contact query parameters. Old room URLs redirect through normal login to the signed-in role's messages page; no media or conferencing provider is loaded.

Existing stored meeting records are retained as history, not deleted. The existing storage schema and archival reference checks remain compatible. Legacy meeting modules are no longer loaded by any live page; this change does not claim a destructive cleanup of archived source. New demo fixtures do not add meetings. Account, message-contact authorization, inbox separation, drafts, unread receipts and sending continue through the original messages module.

Overview layout is now composed directly by dashboard-overview.js rather than rearranged later into different nested role grids. A compact role header, consistent statistic row, paired analytics and a predictable table grid share spacing and theme tokens. Secondary tables sit side by side at desktop widths and stack on narrow screens. Full ledgers keep their search/edit/delete handlers and contain horizontal overflow inside keyboard-accessible table regions. No booking, payment, registration or team record is rewritten by the presentation.

Checks: dashboard-messages-browser.cjs logs in through the normal form for each role, visits each dashboard tab, verifies messages-only navigation and legacy redirects, sends a real local message, preserves historical records, and captures 24 overview size/theme combinations (1440/768/390/320; light/dark; three roles). Unit messaging, dataset and account/overview regressions are retained. Existing meeting-feature browser tests describe retired behavior and are not evidence for the new messaging-only flow.
