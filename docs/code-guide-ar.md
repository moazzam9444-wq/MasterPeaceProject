# دليل قراءة كود KICKS

المشروع يستخدم HTML وCSS وJavaScript فقط. ابدأ بالصفحة، ثم ملف التنسيق، ثم ملف التفاعل المرتبط فيها. لا تحتاج framework لتشغيله.

## كيف يمشي التعديل؟

1. الصفحة تحمل `data-store.js` أولاً لقراءة البيانات.
2. `account.js` يقرأ الحساب المسجّل من الجلسة. الداشبورد يفحص مطابقته للدور الموجود في `data-dashboard`.
3. `getVisibleRecords()` يعيد سجلات اللاعب أو المالك أو الأدمن.
4. `openEditor()` يعرض النموذج. `schemas` يحدد اسم ونوع كل حقل؛ و`columns` يحدد أعمدة الجدول.
5. عند الضغط على حفظ، `validate()` يفحص البيانات. `saveRecord()` يحدث عداد المشاركين عند الحاجة.
6. `KicksStore.save()` يحفظ السجل في المتصفح، و`renderDashboard()` يعيد عرض القسم.
7. عند العودة إلى Overview، الإحصائيات تحسب نفسها من البيانات المحفوظة. الصفحات المفتوحة الأخرى تحتاج إعادة تحميل.

## كيف حسبنا الإحصائيات؟

- `getStatistics()`: أعداد الحجوزات والمشاركات، وقيمة الحجوزات المؤكدة والمكتملة. هذه قيمة الحجوزات وليست مدفوعات.
- `renderBarChart()`: يستقبل أعداداً حقيقية ويحوّلها إلى ارتفاع أعمدة CSS.
- `renderDonut()`: يحسب نسبة كل حالة ويعرض دائرة مع قائمة توضيحية.
- `renderBookings()` و`renderEvents()`: يعرضان جداول الحجوزات والمشاركات المناسبة للدور.
- إذا لم توجد بيانات، يظهر صفر أو رسالة فارغة؛ لا نولد أرقاماً عشوائية.

## مصطلحات ستراها كثيراً

- `find`: البحث عن سجل واحد، مثل ملعب حسب رقمه.
- `filter`: تكوين قائمة جديدة تحتوي السجلات المطابقة لشرط.
- `map`: تحويل كل عنصر، مثلاً تحويل السجلات إلى كروت HTML.
- `join('')`: جمع أجزاء HTML في نص واحد.
- `dataset`: قراءة صفات مثل `data-id` و`data-edit` من الزر.
- `structuredClone`: نسخ البيانات حتى لا تعدل الأصل مباشرة.
- `JSON.stringify` / `JSON.parse`: تحويل البيانات إلى نص للحفظ، وإعادتها إلى بيانات عند القراءة.
- `?.`: قراءة قيمة إذا كان العنصر موجوداً، لتفادي خطأ عند غيابه.
- `escapeHtml()`: تحويل رموز مثل `<` إلى نص آمن قبل إدخاله في `innerHTML`. احتفظ بهذه الخطوة.

## تعديل آمن

عدّل جزءاً صغيراً ثم جرّبه. عند تغيير الألوان العامة، ابدأ بمتغيرات `style.css`. لا تغير أسماء IDs في HTML إلا مع تحديث JavaScript الذي يستخدمها. لا تغير مفتاح `kicks-data-v2` إذا أردت الاحتفاظ بتعديلات المتصفح. قواعد الحذف تمنع ترك حجز أو حدث مرتبط بملعب محذوف.

الحسابات محلية لهذا المتصفح. فحص الدور في الواجهة ليس حماية على مستوى السيرفر. عند ربط .NET لاحقاً، يجب أن ينفذ السيرفر الهوية والصلاحيات والأسعار والتوفر. يمكنك استبدال عمليات `KicksStore` بطلبات API مع الإبقاء على العرض منفصلاً.


`js/account.js` يدير إنشاء حساب اللاعب/صاحب الملعب، مطابقة كلمة المرور، الجلسة والنافبار. حساب الأدمن مجهز مسبقاً ولا يوجد له تسجيل عام. بعد دخول اللاعب نعود للهوم، ومن قائمة صورته نفتح البروفايل أو الداشبورد. ملف `docs/integration.md` يشرح حدود التخزين المحلي والربط المستقبلي.


## تخصيص الأدوار والحساب
- اللاعب: حجوزاته، مباريات انضم إليها، وبطولات فريقه.
- صاحب الملعب: ملاعبه ومبارياته وبطولاته، مع إحصائيات الحجوزات الخاصة بملاعبه دون قسم حجوزات منفصل.
- الأدمن: إدارة الملاعب والحجوزات والمباريات والبطولات والمستخدمين.
- البروفايل لجميع الأدوار: صورة، اسم، بريد، هاتف، مدينة وعنوان. تغيير كلمة المرور يتطلب الحالية وتأكيد الجديدة.
- نبذة الملعب وميزاته يكتبها صاحب الملعب؛ الميزات تفصل بأسطر أو فواصل. التقييم لا يظهر ضمن نموذج صاحب الملعب.
- الزائر يتصفح الصفحات؛ الحجز والانضمام والتسجيل تتطلب تسجيل الدخول.

## خطوات JavaScript الأساسية في المشروع

- `for` تمرّ على السجلات واحدة واحدة. `if` يفحص شرطاً، و`continue` يتجاوز السجل غير المطابق.
- عند قراءة فورم، نمرّ على `FormData` ونضع كل قيمة في كائن باسم الحقل نفسه.
- صفحات الملاعب والمباريات والبطولات تقرأ بياناتها مباشرة من `KicksStore.list()`؛ لا تحتاج ملفات تحميل بيانات منفصلة.
- الدوال المشتركة للحفظ والدخول والصلاحيات بقيت موجودة حتى لا نكرّر المنطق أو نفقد التحقق.
- بيانات الموقع محفوظة بمفتاح `kicks-data-v2` في `localStorage`، ومعرّف الحساب الحالي بمفتاح `kicks-session-v2` في `sessionStorage`.
- `tests/accounts-regression.cjs` يفحص الحسابات والحجز بذاكرة منفصلة؛ لا يغيّر بياناتك. `scripts/create-admin.cjs` أداة إنشاء الأدمن وليست جزءاً من واجهة الموقع.
